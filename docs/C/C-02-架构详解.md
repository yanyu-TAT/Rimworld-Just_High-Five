# C-02 架构详解

> 系统设计细节与架构决策。原版 API 的具体签名与行为见 `docs/C/C-05-原版API简述.md`。

## 一、总体结构

本模组是一个**纯扩展式**模组：不干预原版流程，只在原版提供的扩展点上追加一个社交互动。

```
Defs/                        Source/                        原版
─────────────────────────────────────────────────────────────────────────
InteractionDef "Clap"  ──►  InteractionWorker_Clap
   workerClass                 ├─ RandomSelectionWeight()  ◄── Pawn_InteractionsTracker
                               │     └─ 触发权重 + 排除项        .TryInteractRandomly()
                               └─ Interacted()              ◄── TryInteractWith()
                                     ├─ ClapUtility.RollOutcome()     发生实际互动时
                                     ├─ AddInteractionThought()  ──► 情绪 + 好感
                                     ├─ Hediff_ClapBuff          ──► 12h 随机增益
                                     └─ Hediff_ClapCooldown      ──► 24h 冷却（双方）
                                     └─ ClapEffects.PlayPerfect() ──► 音效 + 黑闪特效
                                                                      （FleckDef / SoundDef）
ClapSettings : ModSettings ──► 原版 Dialog_ModSettings（音量滑块 + 试听）
```

## 二、互动生命周期（我们的代码何时被调用）

```
① 每 60 tick，原版为每个 pawn 掷「想不想社交」的 MTB
② 命中 → 遍历同派系已生成 pawn（Shuffle）
③ 对每个候选人：过滤（自身/不可互动/敌对）→ 对全部 InteractionDef 加权抽取
      └─► 我们的 RandomSelectionWeight(initiator, recipient) 被调用
          · 返回 0 → 本次不被选中（非人化/抱着人/冷却/仇视/无手在这里排除）
④ 抽中「击掌」→ TryInteractWith(p, Clap)
      · 原版门禁：距离 ≤6 格 + 视线 + 双方清醒未燃烧能说话 + 120 tick 硬下限
⑤ 无 initiatorThought/recipientThought（我们留空）→ 不自动加想法
⑥ 技能经验（initiatorXpGainSkill = Social）
⑦ 可能转打架（社交斗争）——转打架则跳过 ⑧
⑧ ─► 我们的 Interacted(initiator, recipient, ...) 被调用
      · 抽取四档结果
      · 写入情绪 / 好感度 ThoughtDef
      · 完美档：抽取并施加 12h 增益 / 灵感
      · 完美档：在双方中点播放音效与黑闪特效
      · 双方写入 24h 冷却
⑨ 原版继续：生成互动气泡 → 更新双方 lastInteraction 时间戳 → 写社交日志 → （我们返回 null 则不发信）
```

**要点**：`RandomSelectionWeight`（③）会被**大量高频调用**（对每个候选人都要算一遍），必须廉价、无副作用、不写日志；所有副作用只能出现在 `Interacted`（⑧）。

## 三、状态载体设计

| 状态 | 载体 | 生命周期 | 持久化 |
| --- | --- | --- | --- |
| 24h 互动冷却 | `Hediff_ClapCooldown`（隐藏） | 24h 后自动过期 | Hediff 随 Pawn Scribe |
| 12h 随机增益 | `Hediff_ClapBuff`（单实例） | 12h 后过期；被更高档覆盖 | Hediff 随 Pawn Scribe |
| 情绪 / 好感度 | 原版 `Thought_Memory` / `Thought_MemorySocial` | 由 `ThoughtDef.durationDays` 决定 | 原版记忆系统 |
| 音效音量缩放 | `ClapSettings`（`ModSettings`） | 玩家手动修改 | 原版选项文件（`ExposeData` + `WriteSettings`） |

**设计原则**：

- **每 Pawn 至多一个** `Clap_Buff`：等级用 `severity`（1/2/3）；时长交给原版 `HediffComp_Disappears`；合并规则（取最高 + 同级/高级覆盖时长）写在 `Hediff_ClapBuff` 类内
- **不使用裸 static 字典**保存任何状态（存读档会丢/串档）；`ClapSettings` 虽以静态属性暴露，但数据本体由原版 `ModSettings` 承载并参与序列化
- **定时失效一律用原版 `HediffComp_Disappears`** —— `SetDuration(int ticks)` 可**随时**修改持续时间，字段与存档序列化均由原版组件承担；不自己写 `Tick` / `ShouldRemove` / `ExposeData`（详见 `C-05` §7.3）

## 四、判定顺序（重要）

`RandomSelectionWeight` 内的短路顺序（从廉价到昂贵）：

```
1. Inhumanized（被非人化的 pawn 不参与社交）→ return 0
2. 手上抱有 pawn（initiator.IsCarryingPawn()）→ return 0
3. 冷却判定：按 OR 口径（两人都冷却才算冷却中）→ return 0，开关 ClapUtility.CooldownRequiresBoth
4. 仇视判定：min(双方 opinion) <= HostileOpinionThreshold → return 0
5. 双方各至少一只可用的手（ClapUtility.TryGetHand）→ return 0
6. 返回 BaseSelectionWeight（常数；ClapDebug.MoreClapHands 开启时 × WeightMultiplier）
```

**要点**：该函数在抽取时按「每个候选 × 每个 `InteractionDef`」各调用一次，因此判定按成本从低到高排列（手部判定需遍历全身部位，最贵，置于最后）。**距离与视线等几何门禁由原版 `Pawn_InteractionsTracker.CanInteractNowWith` 负责，本函数不做也不应做位置校验**（依据见 `C-05` §1.10.1）。

## 五、时序与边界情况

| 情况 | 处理 |
| --- | --- |
| `Interacted` 中 recipient 已死亡/被移除 | 入口校验后直接 return（校验排在副作用之前） |
| 抽取增益时 `GetRandomAvailableInspirationDef()` 返回 null | 按降级策略处理（见计划文件待确认项 2） |
| 双方中一人已有更高档增益 | 低档完全忽略（不影响等级与时长） |
| 互动转打架（social fight） | 原版不会调用我们的 `Interacted`，无副作用 |
| 互动发生在异派系（如访客） | 由原版门禁决定；`AddInteractionThought` 内部自行判空 |
| 特效播放时双方不同图 / 已 despawn | `ClapEffects.PlayPerfect` 先校验再生成，直接跳过 |
| 音效 Def 或 FleckDef 缺失（Def 加载失败） | 各自 `Log.Error` 后跳过对应部分，不影响结算本身 |

## 六、表现层：特效与音效

完美击掌时由 `ClapEffects.PlayPerfect(initiator, recipient)` 统一负责表现，全部走原版 Fleck / SoundDef（零补丁、零第三方库）：

| 元素 | 实现 | 关键约束 |
| --- | --- | --- |
| 音效 | `Clap_HandClap`（`AudioGrain_Folder` 从 `Sounds/Clap_Your_Hands/` 取 3 个变体之一），在双方中点以 `SoundInfo.InMap` 播放 | 最终音量 = Def 的 `volumeRange`（0.32~0.44）× 设置项的 `volumeFactor` |
| 闪电纹样 | 两层 Fleck：`Clap_BlackFlashBoltCore`（`Mote` 暗红实体）+ `Clap_BlackFlashBoltGlow`（`MoteGlow` 亮红外圈，放大 1.25 倍），共用同一朝向 | `MoteGlow` 走发光路线，暗色必须有 `Mote` 层承载 |
| 火花 | `Clap_HandSpark`（`FleckSystemThrown` + `ChargeSpark` 贴图），12 枚水平随机飞散 | 抛物线靠 `archHeight` / `archDuration`，减速靠 `speedPerTime` 负值（详见 `C-05` §6.4.2） |
| 随机性 | 闪电用 `randomGraphics`（4 张变体，按 fleck id 抽取）+ 运行时随机 `rotation` | 一张贴图即可产生多种观感 |

**顺序**：音效在 `ShouldSpawnMotesAt` 守卫**之前**播放 —— 该守卫只决定是否绘制，不应连带砍掉声音（听觉由 `distRange` 自行衰减）。

**资源规范**：贴图纯白 + 透明底 + 2 的幂尺寸（颜色一律由 Def 的 `color` 提供，`Graphic_Fleck` 的颜色是乘算）；音效为单声道 44.1 kHz 16-bit WAV（< 300 KB，见 `C-05` §5.1）。

## 七、设置页

`ClapSettings : ModSettings` + `ClapYourHandsMod` 覆写 `SettingsCategory()` / `DoSettingsWindowContents()`，同样不需要补丁或第三方库：

| 项 | 实现 |
| --- | --- |
| 入口 | `SettingsCategory()` 返回非空即让原版模组菜单出现「Mod 选项」，无需任何注册（见 `C-05` §10.1） |
| 音量 | `VolumeScale`（0~1，5% 步进滑块），播放时写入 `SoundInfo.volumeFactor`（乘算，不干扰玩家的 `Prefs.VolumeGame`） |
| 试听 | 在镜头中心 `SoundInfo.InMap` + `testPlay = true`；不用 `PlayOneShotOnCamera`（位置无效且会报错，见 `C-05` §10.4） |
| 持久化 | `ExposeData()` 内 `Scribe_Values.Look`，原版在设置窗口关闭时自动 `WriteSettings()` |
| 读取 | 静态入口 `ClapYourHandsMod.Settings`，播放热路径直接读，无需查找 |

## 八、为什么不写 Harmony 补丁

见 `docs/C/C-03-项目长期记忆.md` 的 ADR-1。简述：原版扩展点已足够覆盖本功能全部需求（互动、想法、增益、特效、音效、设置页），补丁只带来加载顺序风险与版本脆弱性，且会让「击掌」与其它模组的同类补丁产生冲突面。
