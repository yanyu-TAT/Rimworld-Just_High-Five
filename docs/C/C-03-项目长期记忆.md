> 本项目长期有效的事实与约定。新 Agent 接手时**先读本文件**，再读 `AGENTS.md` 与 `docs/C/C-05-原版API简述.md`。

## 一、项目技术基线

| 项 | 值 |
| --- | --- |
| 游戏版本 | RimWorld 1.6 |
| 目标框架 | `net472` + `LangVersion 10.0`，SDK 风格 csproj |
| 模组包 ID | `yanyu.clapyourhands` |
| 程序集名 | `Clap_Your_Hands.dll` |
| 命名空间 | `ClapYourHands` |

### 构建环境注意事项

- 沙箱/CI 环境下需设置 `DOTNET_CLI_HOME` 到工作区内的 `.dsh-dotnet`（已加入 `.gitignore`）
- 引用路径指向本机 Steam 安装目录，**CI 上不可编译**；构建与测试均在本机完成
- 工作区 Python 虚拟环境必须用 Windows 原生解释器创建（PATH 上的 MSYS2 `python` 会建出 POSIX 布局的 venv，`pyenv_install` 会报「no usable interpreter」）

## 二、架构决策记录

### ADR-1：零 Harmony 补丁（重要）

**决策**：本项目不使用 Harmony 补丁，全部功能通过原版扩展点与 Def 实现。

**理由**：RimWorld 1.6 的社交互动系统已提供完整扩展点——`InteractionDef` + `InteractionWorker` 会自动进入原版随机社交池，`Interacted` 是官方虚方法扩展点，`AddInteractionThought` 是 public static，Hediff 的 `stages[]` 可直接表达增益。补丁只会带来加载顺序风险与版本脆弱性。

**约束**：任何新需求先问「原版有没有扩展点/Def 字段能表达」，再考虑代码，**最后**才考虑补丁；引入补丁前必须先向用户确认。

**证据**：见 `docs/C/C-05-原版API简述.md` 一、社交互动系统。

### ADR-2：运行时状态用 Hediff 承载，禁止裸 static

**决策**：24h 冷却、12h 增益等随 Pawn 的状态一律用 `HediffDef` 承载。

**理由**：Hediff 随 Pawn 自动参与 Scribe 存读档，自动过期，天然多存档隔离；裸 `static Dictionary` 会在存读档后丢失或串档（`AGENTS.md` 高频错误 #3）。

**唯二例外**：
- 开发期调试开关（`ClapDebug.MoreClapHands` / `AlwaysPerfect`）有意使用裸 `static bool` —— 它**不需要**跨存读档保持，且本应随游戏重启重置
- `ClapYourHandsMod.Settings` 是静态属性，但数据本体由原版 `ModSettings` 承载并参与序列化，静态只是访问入口

### ADR-3：概率曲线用原版 `SimpleCurve`

**决策**：好感度 → 概率/权重的映射统一用 `SimpleCurve`（`Verse.SimpleCurve`）。

**理由**：原版 `InteractionWorker_DeepTalk` 即此范式（`0.075f × CompatibilityFactorCurve.Evaluate(...)`），点位即调参入口，避免手写阶梯 if-else。

### ADR-4：表现层资源全部自制，颜色/音量交给 Def

**决策**：贴图与音频均为自制或可商用授权素材；贴图一律**纯白 + 透明底**、颜色由 Def 的 `color` 提供；音量由 Def 的 `volumeRange` 提供，玩家侧缩放只经 `SoundInfo.volumeFactor`。

**理由**：
- `Graphic_Fleck` 的最终颜色是 `base.Color × drawData.color` **乘算** —— 彩色贴图会被二次染色成脏色
- 透明底在 `Mote` 与 `MoteGlow` 两种 shader 下都安全
- 颜色/音量写在 Def 里，调参**不需要重新编译**

**约束**：禁止截取他人作品（如动画画面、音轨）作为素材；贴图与音频的格式规范见 `C-05` §5.1、§6.4.1。

## 三、命名与文本约定

- 新 Def 的 `defName` 统一以 `Clap` 前缀（如 `Clap`、`Clap_Bad`、`Clap_Buff`、`Clap_BlackFlashBoltCore`、`Clap_HandClap`），保证全局唯一
  - ⚠️ `ClapDefOf` 的字段名必须与 `defName` 一致，因此**不同类型不能重名**（例如 `ThoughtDef Clap_Perfect` 已占用，音效只能叫 `Clap_HandClap`）
- 代码内文本 → `Keyed`，键名格式 `ClapYourHands.<域>.<语义>`（如 `ClapYourHands.Settings.Volume`）
- Def 内文本 → `DefInjected`，文件名与 `Defs/` 一一对应
- 中英语言文件**逐键对称**，不允许单边缺失
- 资源目录约定：
  - 贴图 `Textures/ClapYourHands/<Name>.png`（`texPath` 写 `ClapYourHands/<Name>`，不含 `Textures/` 与扩展名）
  - 音频 `Sounds/Clap_Your_Hands/*.wav`（`clipFolderPath` 写 `Clap_Your_Hands`，**同一目录只放同一效果的变体**，`AudioGrain_Folder` 会全量随机取）

## 四、已核实的关键原版行为（易踩坑）

1. **没有「直接增加好感度」的 API** — opinion 是派生值，必须经 Social 型 `ThoughtDef` + `Pawn_InteractionsTracker.AddInteractionThought` 写入；且写入时会乘 `SocialImpact` 缩放，字面 +3/+5 不成立。
2. **`lastInteractionTime` 是 private** — 自定义互动的冷却只能自建载体。
3. **敌对已被原版排除** — `TryInteractRandomly` 中显式 `pawn.HostileTo(p)` 跳过；「仇视」需自己在权重里返回 0。
4. **社交距离上限 6 格** — `SocialInteractionUtility.MaxInteractRange = 6f`（含视线检查）。
5. **互动有 120 tick 硬下限** — 两次任意互动之间至少间隔 120 ticks；`InteractionDef.ignoreTimeSinceLastInteraction` 可跳过该检查。
6. **`Interacted` 之后原版仍会执行**：气泡生成 → 双方冷却时间戳更新 → `PlayLogEntry_Interaction` 入日志 → letter 发送，所以不要在这些环节重复做事。
7. **`RandomSelectionWeight` 会被「每候选 × 每 Def」调用**，且开发者菜单会**不带门禁**直接调用它 —— 里面不能读位置、不能做昂贵计算（见 `C-05` §1.10.1、§1.11）。
8. **Fleck 的 `height` 不是世界 Y 轴**，而是屏幕向上（世界 +Z）的绘制偏移；`worldPosition.y` 在绘制时被 `altitudeLayer` 覆盖 —— 抛物线只能靠 `archHeight` / `archDuration` 表达，`acceleration` 的 y 分量无视觉效果（见 `C-05` §6.4.2）。
9. **`SubSoundDef.volumeRange` 的单位是百分比**（默认 `50` 即 0.5 音量）；运行时倍率走 `SoundInfo.volumeFactor`（见 `C-05` §10.3）。
10. **设置页入口只需 `Mod.SettingsCategory()` 返回非空**，无需任何注册；`Widgets.HorizontalSlider` 在 1.6 是**返回值式**而非 `ref`（见 `C-05` §10.1、§10.2）。
